# CreditRisk — AI-Powered Credit Risk Analysis Platform

An end-to-end credit risk assessment system that combines **machine learning scoring** with **LLM-driven analyst insights**, built as a full-stack application with a Python backend and Angular frontend.

The platform predicts loan payback probability using a trained logistic regression pipeline, then augments the result with structured analysis generated by an LLM grounded in internal policy documents via Retrieval-Augmented Generation (RAG).

## Motivation

Credit risk assessment in financial institutions typically involves both quantitative scoring and qualitative analyst review. This project bridges the two by:

1. **Scoring** loan applications with a calibrated ML model trained on historical data.
2. **Generating structured analyst-ready insights** using an LLM that references internal policy documents, producing actionable review notes rather than opaque predictions.

The goal is to demonstrate a production-style AI system where ML inference and generative AI work together in a single request pipeline, with a clean separation of concerns across the full stack.

## System Overview

The platform follows a straightforward request flow:

```
User submits loan application (Angular SPA)
        |
        v
POST /api/payback/single (FastAPI)
        |
        v
scikit-learn pipeline: predict payback probability
        |
        v
Extract top feature contributions (model signals)
        |
        v
LangChain + RAG: retrieve relevant policy docs from Chroma
        |
        v
LLM generates structured JSON analysis (insights, risks, actions)
        |
        v
Combined response returned to frontend
        |
        v
Results displayed: decision, probability bar, full analyst report
```

**Decision logic** is threshold-based on the predicted probability:

| Probability Range | Decision    |
|-------------------|-------------|
| >= 0.85           | **Approve** |
| 0.60 - 0.84      | **Review**  |
| < 0.60            | **Reject**  |

## Architecture

The project uses a **monorepo layout** with two independent applications:

```
CreditRisk/
├── apps/
│   ├── backend/      # Python — FastAPI, ML, RAG, LLM
│   └── frontend/     # TypeScript — Angular 20 SPA
└── infra/            # Infrastructure (Docker, deployment — planned)
```

- **Backend**: Single FastAPI service handling inference, LLM orchestration, and RAG retrieval in a synchronous pipeline.
- **Frontend**: Standalone Angular application communicating with the backend over REST. Signal-based state management, no external UI library.
- **No database**: The system is stateless per request. The only persistence is the Chroma vector store index for RAG, generated on first startup from the bundled policy documents.

## ML Pipeline

The machine learning model is a **logistic regression pipeline** built with scikit-learn, trained and calibrated externally on a Kaggle loan payback dataset.

**Preprocessing steps** (embedded in the pipeline):

- **One-hot encoding** for categorical features: gender, marital status, education level, employment status, loan purpose
- **Ordinal encoding** for credit grade/subgrade (A1 through F5)
- **Log1p transformation** with imputation on numeric features
- **Standard scaling** on numeric columns
- **Custom ratio/interaction features** via a `RatioInteractionImputer` transformer

**Inference and explainability**:

- `predict_proba` returns the payback probability for the positive class.
- Feature contributions are computed from the linear model coefficients multiplied by the transformed feature values, producing **top positive and top negative contributors** per prediction. These are passed as model signals to the LLM for grounded analysis.

The trained model artifact (`.pkl`) is loaded at startup and is not included in the repository — see [Related Work](#related-work) for the training repository.

## LLM and RAG Integration

After ML scoring, the system generates a structured analyst report using LangChain:

**Retrieval-Augmented Generation (RAG)**:

- **Vector store**: ChromaDB with local persistence, using OpenAI `text-embedding-3-large` embeddings.
- **Knowledge base**: Five synthetic internal policy documents covering underwriting policy, review playbooks, eligibility matrices, adverse decision guides, and financial document interpretation.
- **Chunking**: `RecursiveCharacterTextSplitter` with 1000-character chunks and 200-character overlap.
- **Retrieval**: Top-5 most relevant chunks are retrieved per request based on a query built from applicant data and model signals.

**LLM Chain**:

- **Model**: OpenAI `gpt-5.4-mini` via LangChain's `ChatOpenAI`.
- **Prompt design**: The LLM acts as an internal bank analyst copilot. It receives applicant data, model signals (top contributors), and retrieved policy context. It is instructed to produce business-friendly language and avoid demographic bias.
- **Output**: Structured JSON parsed into a Pydantic model with the following sections:
  - Applicant snapshot
  - Supportive factors
  - Risk factors
  - Policy/process insights (with source document references)
  - Missing information
  - Recommended review actions
  - Analyst rationale draft
  - Confidence limitations

## API Reference

### `POST /api/payback/single`

Submits a loan application for credit risk scoring and AI analysis.

**Request body**:

```json
{
  "gender": "Female",
  "marital_status": "Single",
  "education_level": "High School",
  "employment_status": "Self-employed",
  "loan_purpose": "Other",
  "grade_subgrade": "C3",
  "annual_income": 29367.99,
  "debt_to_income_ratio": 0.084,
  "credit_score": 736,
  "loan_amount": 2528.42,
  "interest_rate": 13.67
}
```

**Response**: Returns a loan decision (`Approve` / `Review` / `Reject`), the payback probability, and structured LLM-generated insights including supportive factors, risk factors, policy insights with source references, missing information, recommended actions, and an analyst rationale draft.

### `GET /health`

Health check endpoint returning `{"status": "ok"}`.
